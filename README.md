# FeedForge

Сборка промо-фидов по сетям: источники (ссылки и файлы), настройки и кэш для каждой сети,
проверка свежести, конвертация. Результат: сокращённый JSON в формате Едадил (Старт), предрасчёт (Предрасчёт) и Excel с картинками (кнопка «JSON → Excel», локально). Выгрузка на S3 и картинки на S3 — следующие шаги.

## Сборка
    dotnet build
    dotnet publish -c Release        # один exe: bin\Release\net8.0-windows\win-x64\publish\FeedForge.exe

## Структура
    Program.cs
    FeedForge.csproj
    ru_geo.tsv                  справочник регионов (встроен в exe)
    Core/                       Converter, ImageRecoder, RecodeOptions, RuGeo      (из JsonToExcel)
    Storage/                    NetworkModels, AppStorage, SourceCache, S3, UiSettings
    Ui/                         NetworksForm, NetworkDialogs (сеть, настройки, S3), S3Dialogs (обзор бакета), RecoderForm, MainForm (старое окно JSON → Excel)

## Данные программы
    %AppData%\FeedForge\app.json          глобальные настройки
    <папка данных>\networks\<id>.json       по файлу на сеть
    <папка кэша>\<сеть>\                    скачанные исходные файлы + manifest.json
При первом запуске наборы из старой программы (%AppData%\JsonToExcel\settings.json) импортируются как сети.

## S3
Настройки → вкладки «S3: входящий 1/2» (только чтение: откуда берём сырые фиды) и «S3: исходящий» (куда будет выгружаться результат; загрузка — следующий шаг).
Источник сети может быть адресом `s3://бакет/папка/` (все json/xml/yml из папки) или `s3://бакет/папка/файл.json`.
Подключение к адресу определяется по имени бакета, поэтому у двух входящих подключений бакеты должны называться по-разному.
Кнопка «Сети из S3...» создаёт сеть из каждой отмеченной папки.

## Сборка JSON
Два прохода по исходному файлу: 1) отбор товаров по настройкам сети (охват магазинов, разброс цен, «только price_old», гео) и лимит офферов;
2) потоковая запись: офферы копируются как есть (все поля), каталоги получают урезанный список offers, пустые каталоги не пишутся.
Результат: <папка результатов>\<сеть>\json\<сеть>.json (при нескольких файлах в сети — по подпапке на файл).
Лимит: «на каждый каталог» — не больше N офферов в каждом каталоге; остальные режимы — не больше N офферов в файле. Состав при лимите стабилен: шире охват, затем перемешанный по хэшу названия порядок (ассортимент не обрезается по алфавиту).

## Картинки и выгрузка на S3 (JSON)
В настройках сети: «Загружать JSON на S3» и «Сжимать картинки и класть на S3».
Схема в бакете исходящего подключения: <корневая папка>/<сеть>/<сеть>.json и <корневая папка>/<сеть>/images/ (+ реестр _images.json).
Картинка с тем же адресом и теми же настройками сжатия повторно не скачивается и не загружается (реестр). Сжатие подгоняется под максимальный вес (по умолчанию 1000 КБ);
при невозможности скачать картинку в оффере остаётся исходная ссылка. «Предрасчёт» показывает, сколько картинок уже на S3 и сколько нужно загрузить.
Товар определяется только по названию (description), как в FeedChecker.

## История запусков
Вкладка «История»: последние 100 запусков сети (дата, режим, статус, файлов, офферов, картинки новых / уже было / ошибок, время). Хранится в <папка данных>\history\<id>.json.
Офферы с картинкой меньше 400 px можно исключать (галочка в настройках сети); при лимите на их место берутся следующие товары.

## Несколько файлов в один JSON
Галочка «Объединить файлы сети в один результат»: каждый файл (или каждый файл из S3-папки) — отдельный магазин, товар определяется по названию, охват магазинов и разброс цен считаются по всем файлам.
Результат — один JSON: каталоги и офферы всех файлов. Если id офферов или каталогов у разных файлов совпали, у второго и следующих файлов к id добавляется префикс «номер файла_» (ссылки в каталогах переписываются). Остальные поля офферов не меняются.
Разбивка на несколько JSON (по регионам/магазинам) для JSON не применяется: регионы и адреса остаются каталогами внутри одного файла. Лимит «на каждый каталог» ограничивает офферы в каждом каталоге.

## YML в JSON
YML-файлы (по одному или вместе с JSON) тоже собираются в JSON: товар определяется по названию, одно название — один оффер, цена выбирается режимом «Цена» после проверки разброса цен между файлами.
Из YML строится один каталог: id yml_russia, target_regions ["Россия"], date_start — сегодня, date_end — через N дней (настройка сети, по умолчанию 7), conditions — стандартный текст или свой. Поля оффера: id, description, image, price_new, price_old (если есть oldprice).
Если рядом есть JSON-каталоги, id YML-офферов получают префикс «yml_».
«Не проверять разброс цен» — для JSON с региональными каталогами, где у каждого региона своя цена. Лимит по умолчанию «на каждый каталог».

## Режимы отбора
«Как в исходных файлах» (по умолчанию для новых сетей): без фильтров по цене и магазинам, у каждого каталога свои цены — товаров максимум.
«Одна цена на товар»: проверка разброса цен (5%), цена по режиму «Максимальная», охват магазинов 95%.
«Свои настройки»: показываются расширенные параметры (старые сети остаются в этом режиме).

## Офферы без рабочей картинки
Оффер, у которого нет ключа image или ссылка не начинается с http:// / https:// (например, относительная «/upload/…»), в JSON не попадает; при лимите на его место берётся следующий товар. Ссылки не достраиваются.
